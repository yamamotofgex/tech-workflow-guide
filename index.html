情報応用実践 第７回 ／ フローで具体化する

ひび割れ点検：As-IsとTo-Beを描く５ステップ

現場での目視確認から始め、AIによる検出・計測と調書作成の支援を考える。

今回書く・変える部分AI・システム疑問・メモ調査・検討の反映
As-Is 01 / 05

前半の情報から、一人の一場面を選ぶ

0〜3分
講師の声かけ

リーンキャンバスの「②お客様」と「①課題」を見て、誰のどの場面を描くか選びましょう。

「②お客様」から対象者を選び、「①課題」が起きる場面を補います。目的は、その人が達成したいこととして書きます。

書くときのポイント場面が広いときは１回の具体的な出来事を仮置きします。前半の引継ぎ資料の「対象者と場面」も使えます。

As-Is 02 / 05

「①課題」を、今の行動に言い換える

3〜5分
講師の声かけ

「①課題」を見て、「②お客様」は何をしているときに困っていますか。その行動を１箱に書きましょう。

記入例（仮）：「点検員が、幅の計測・現場での記録に手間をかけている」。そこから「幅などを計測し、現場メモを残す」と書きます。

書くときのポイント箱の中は「○○をする」という今の行動にします。分からない部分は仮置きし、確認したいことを箱の外に残します。

As-Is 03 / 05

直前と直後の行動を足す

5〜8分
講師の声かけ

その直前に何をしていますか。その直後には何をしますか。

直前に「現場で目視確認」、直後に「損傷箇所を撮影」を置きます。実際には計測と撮影を往復する場合もあり、ここでは通常の順序を簡略化しています。

書くときのポイント箱は行動の順に矢印でつなぎます。疑問は工程の外に置き、作業の流れと区別します。

As-Is 04 / 05

現場へ行くところから、調書を残すまで広げる

8〜12分
講師の声かけ

この場面の始まりと終わりまで、足りない行動を書き足しましょう。

現場への移動、写真と情報の整理、点検調書への記入、確認・保存を追加します。写真は、現場で確認した状態を記録する資料として扱います。

書くときのポイント現場メモを調書に転記する作業まで描くと、現地作業と整理作業の両方の手間が見えます。

As-Is 05 / 05

行動のまとまりに名前を付ける

12〜15分
講師の声かけ

行動を大きなまとまりに分け、上段に見出しを書きましょう。

「現場での目視確認」「計測・撮影と現場情報の記録」「点検調書の作成」の３つに整理します。同じ大枠をTo-Beへ引き継ぎます。

次にすること残り25分で、判断・確認のやり直し・必要な情報を各大枠に追加します。大枠の数はテーマに合わせて変えます。

To-Be 01 / 05

As-Isと同じ対象者・場面・目的から始める

第7回で着手
講師の声かけ

As-Isの対象者・場面・目的と大枠を、To-Beのシートへ写しましょう。

まずAs-Isの流れを参照し、比較する範囲をそろえます。ひび割れ点検を効率化し、確認・計測・記録の時間を減らしたいという目的を共有します。

書くときのポイントこの画面の工程は、比較の起点として写したAs-Isです。次のステップで変えたい作業を選びます。

To-Be 02 / 05

変えたい作業と、その理由を選ぶ

第7回で着手
講師の声かけ

どの作業を、どう楽にしたいですか。変えたい箱を選びましょう。

例では「幅の計測・現場メモ」と「調書への転記」を対象にします。手間や記入ミスを減らせるか、という仮説を置きます。

書くときのポイント現場でひび割れを見る作業は残します。AIを入れる場所と、点検員が担う役割を分けて考えます。

To-Be 03 / 05

「④課題解決方策」を、仮の流れにする

第7回で着手
講師の声かけ

リーンキャンバスの「④課題解決方策」を見て、誰が何をするかを箱に分け、つないでみましょう。

「AIで幅の計測や記録を支援する」という仮の案を、撮影・AI処理・人の確認・調書作成の流れに具体化します。

書くときのポイントAIの出力を確認する人、必要な追加計測、所見を補う作業も置きます。As-Isと比べ、どの手間が変わるかを確かめます。

To-Be 04 / 05

実現に必要な条件を、問いとして残す

第7回から第8回へ
講師の声かけ

この流れを実現するために、何を確かめる必要がありますか。

撮影・通信条件、検出と計測の範囲、人の確認方法、調書に出力できる項目を問いにします。工程のQ番号とメモを対応させます。

書くときのポイントこの段階では分からないことがあって構いません。問いを分担し、資料で確認したことをフローへ戻します。

To-Be 05 / 05

確認した条件をフローへ反映する

第8回も継続
講師の声かけ

調べた条件や決めた運用を、作業とメモへ書き戻しましょう。

参考技術の機器・通信・撮影条件を準備と撮影に反映します。人による確認・追加計測・所見の補足は、この授業例で定める運用として残します。

次にすること次に、同じ対象で所要時間・記録の誤り・確認の負担を比べます。効果は未検証です。AIの処理と確認に増える手間も含めて確かめます。

As-Is ステップ1

この例の前提・参考資料

前半との接続：As-Isは「②お客様」と「①課題」から今の行動を書き出し、To-Beは「④課題解決方策」を具体的な作業へ展開します。図中のリーンキャンバスは説明用の仮の記入例です。

As-Isは、現場で目視確認し、計測・撮影を行い、点検調書へ記録する業務を説明用に簡略化したものです。実際の細かな順序や所要時間は点検方法・対象によって異なります。計測・転記の手間は、確認すべき課題の仮説として示しています。

To-Beは、現場の目視確認を残し、AIでひび割れの検出・幅の計測と帳票作成を支援する設計例です。条件を反映した例も、実地で効果を検証済みという意味ではありません。構造物の健全性の総合診断や、ひび割れ以外の損傷の点検は、この図の対象範囲に含めていません。

参考１：国土交通省「道路橋定期点検要領（技術的助言）」令和6年3月。状態把握の方法と記録の位置付けを確認。

参考２：国土交通省「AI機能付きタブレット端末による点検支援技術（ひびわれ）」BR010036-V0426（2026年3月、1・5・7ページ）。検出・幅の計測・帳票出力と、機器・撮影・通信条件を参照。これは一つの参考技術の条件です。

人による現物との照合、追加計測、確認・修正内容を別に残す手順は、この授業例で定める運用です。製品の標準機能として保証するものではありません。現場で照合する想定のため、現場で解析結果を受け取れる条件を確認します。確認日：2026年10月28日。
